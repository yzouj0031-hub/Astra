# Astra · 星屿与六地旅行

新增 **雨港、烟雨渡、静山寺**，和静屿、星辉乐园、旧维多利亚港共用一个游戏入口、一位探索角色和一份本机旅行册。点击右上角 **「☰ 菜单」** 展开操作，再点 **「旅行地图 ↗」** 选择目的地；新地区里按 **M** 或点「旅行地图」切换，点 **「返航」** 回到离开原世界时的位置与玩法。

| 新地区 | 可以做的事 |
| --- | --- |
| 雨港 · 夜航 | 逛夜市和海角灯塔；到电车站或走近电车按 E 上车，途中按 E 下车；切换雨天与灯光；拍摄明信片 |
| 烟雨渡 | 走过石桥与沿河街巷；从真门洞走进听雨茶馆；和路人交谈；在渡口按 E 登乌篷船，W/S 划船、A/D 转向，靠岸按 E 下船 |
| 静山寺 | 走近守卫按 E 开始个人试炼；轻重击、闪避、定身与喝药；获胜后沿庭院北侧台阶进寺，参观山门玉印 |

雨港渡口可直接转往烟雨渡，烟雨渡西北的山寺古道可登山，静山寺入口可以下山返回。地区导览按钮可快速到达关键地点，不必先找路。旅行地图始终提供返回路径。新地区采用按需加载的场景切换，**不是六片地形无缝相连**；旧世界的跨海栈桥、游泳跳水、驾船下船、开水上飞机、建筑与游乐设施照常保留。

旅行册有 **夜市寻灯、茶馆听雨、泛舟一程、山门玉印** 四枚印记，分别通过走进夜市、进入茶馆、划船离开渡口一段距离、击败守卫获得。访问过的地区、地面停留位置和印记仅保存于本机；没有账号或云存档。山门玉印获得后，再访静山寺可以直接进寺。

界面默认收起。新地区的天气、时间、同游、拍照、地图和地区导览集中在右上角「☰ 菜单」；展开菜单会暂停当前地区，按 Esc 或点「× 收起」继续，选择地点后自动收起。移动、上下船、对话与战斗按钮保留在菜单外。原世界也可从右上角展开或收起界面。

新地区统一使用 **WASD / 方向键** 移动、**Shift** 快跑、拖动环顾、滚轮调镜头、**V** 第一/第三人称切换、**E** 互动。触屏设备显示独立摇杆与快跑按钮。试炼使用 **J 轻击、K 重击、空格闪避、Q 定身、R 喝药**，也有屏幕按钮；**E 退出试炼**。打开旅行地图、切后台、窗口失焦时清除输入并暂停该地区。

可直接分享带有 `?journey=rainport`、`?journey=watertown` 或 `?journey=temple` 的地址。原有房间邀请参数可以同时保留。

新地区延续社交同游：同一区域的朋友可看到彼此，跨区域时不会误显示在同一坐标；**山寺战斗与奖励仍为个人进度**，并非多人共同扣同一个 Boss 的血。电车、船只与天气也各自在本地运行。

## 下载与本地运行

下载完整仓库后，运行 `python START_GAME.py`，打开终端给出的本地地址；也可用 `npm run dev`。运行 `npm run package:game` 会在 `dist` 生成可双击打开的「星屿-六地旅行版.html」，三个新地区的脚本和样式、六地的树模型和贴图、玩家角色、老爷车、水上飞机和港区路人的模型全部内嵌（约 15MB），单人模式无需联网。联机仍需联网及有效的房间服务配置。

## 实现与来源

三个地区来自用户提供的 `Rainport-Afterhours-Source.zip`、烟雨渡 HTML 和 `ash-and-jade-source.zip`。场景几何、建筑、天气及战斗规则经过适配后直接由 Astra 渲染，未嵌入其他网站，也不加载第二份 Three.js。原有 MIT 库许可见 `journeys/THREE-LICENSE.txt`。

`journeys/core.js` 负责碰撞与旅行存档；`regions.js` 对接场景与玩法；`runtime.js` 统一输入、相机、界面和场景生命周期；`assets.js` 加载外部 glTF，`foliage.js` 是六地共用的植被装配；另外三个场景文件保留原作的程序建模，烟雨渡的树例外。移出地区时释放其场景资源，原世界停止更新；探索与战斗都使用 Astra 的角色，山寺借用原作武器和程序动作。雨港 r160、山寺 r170 的颜色已显式适配到主游戏的 r128。

六个地区的树都已经换成外部 glTF 模型（见下面的「六地的树」），玩家角色是带骨骼动画的 glTF 模型（来源见 `assets/LICENSES.md`）；老爷车和水上飞机是 Blender 里自建、带真实材质贴图的模型（`blender/tools/build_roadster.py`、`build_seaplane.py`），维多利亚港的路人换成了烘成单网格的 glTF 角色。建筑、桥、帆船与港区轮船、电车，以及其他地区的路人仍是代码拼出来的低多边形。烟雨渡开放茶馆室内，静山寺开放胜利后的寺内展台；其余水乡住宅、雨港多数楼房供外观游览。尚无完整任务剧情、经济系统或全城交通模拟。

### 六地的树

六地共用一套装配：`journeys/foliage.js` 负责实例化、顶点着色器的风和 alpha 卡片，`journeys/assets.js` 负责加载与按色彩管线建材质。这套原来只长在烟雨渡里，其余五地各有一份自己拿圆柱和锥体拼的树，现在统一从这里出。

| 地区 | 换掉了什么 | 现在种的 |
| --- | --- | --- |
| 静屿 | 155 株圆柱棕榈 + 多面体灌木 | 棕榈五种 + 灌木 |
| 星辉乐园 | ~65 棵圆柱加球的树 | 杂树、桦、枫混种 |
| 雨港 | 14 棵行道树 | 针叶与杂树，压暗压冷 |
| 静山寺 | 95 棵 InstancedMesh 锥体 | 松林，压回暗绿 |
| 烟雨渡 | 全部 | 见下表 |

**逐地区的色偏。** 同一批模型原色偏亮偏黄，直接摆进深蓝的夜港和暗绿的山谷会从场景里跳出来——静山寺原来那套锥体树是很暗的墨绿（`#29453a`），换完整片亮了一截，谷地从沉静变得发白。所以每个地区给一个乘在贴图上的暗调色，把树压回本地的调子里。

**两套色彩管线。** 烟雨渡是 `NoToneMapping` + `LinearEncoding`，贴图必须原样通过；其余五地是 sRGB 输出，不打 `sRGBEncoding` 标记会亮一大截。同一张贴图不能同时挂两种 encoding，所以解码一次、按管线各克隆一份（`clone()` 共享 image，各自上传 GPU）。

#### 烟雨渡

| 位置 | 种什么 | 桌面端数量 |
| --- | --- | --- |
| 沿河驳岸 | 垂柳 | 27 |
| 山脚、镇外 | 红枫、杂树、桦 | 70 |
| 广场 | 老樟树 | 1 |
| 墙根、巷道外侧、山脚 | 竹丛 | 18 丛 |
| 山坡 | 层叠松（点景，不多） | 7 |
| 驳岸脚下、山坡 | 细叶灌木 | 46 |

沿河的柳原本只有 10 棵——老布局的步长是 24~40 米，一棵管二十多米河岸，而烟雨渡的招牌恰恰是柳荫夹河。补出来的那些**没有动原来那一组**：步长和种子全保持原样，另开一组用独立随机流撒，落点自动避开已有的树和房子。

全部用 `InstancedMesh` 实例化，按部件和材质各一个 draw call。树皮带平铺贴图和法线贴图，叶片是 alpha 镂空卡片，不再是纯色球体。模型来自 Quaternius 的 Ultimate Stylized Nature Pack（CC0），重新打包过：贴图摘出 GLB 去重、降到 512、树皮转 JPEG，只留用得上的变体。来源与加工方式见 [`assets/LICENSES.md`](./assets/LICENSES.md)。

**柳树、竹、层叠松都是拼的，但不是用方块拼的。** CC0 里没有能用的柳树；竹只有光竿没有叶子；迎客松那种一盘一盘分层的松根本没有现成模型。这三样走同一条路子——**真枝干模型 + 按规则挂上去的 alpha 卡片**，卡片图案由 `scripts/make-plant-cards.mjs` 生成：

- **柳**：骨架用 `DeadTree` 的带贴图枝干，从枝梢按方位角挑挂点，每个挂两片十字交叉的柳条（单片平面侧看会整条消失）。垂长受挂点高度限制，不会插进地面。
- **竹**：竿子是 CC0 模型，叶簇卡片挂在竿子上半段。
- **松**：枝干同样借 `DeadTree`，针盘分六层、每层五到七个方位、每个方位叠两片，层与层之间留空——迎客松就是靠这些空隙成立的。

风是顶点着色器里推的，摆幅分两部分：卡片自身随局部高度弯（柳条最明显），加上一个逐实例的整体摆幅——挂在竹竿高处的叶簇是整片跟着竿子晃，靠它自己那点局部高度差撑不起来。每株一个随机相位，不会整片同步摇。阴影贴图走的是 depth 材质，不含这段位移，因此影子不跟着摆；叶片卡片本身不投影，上千片窄条会把 shadow map 打成噪点。

**手机端减树。** 三角形从桌面端的 102.0 万压到 48.6 万（47.6%）——镇子本身的静态几何就占 28.2 万且动不了，所以树这一块砍到了三成以下。减的是**株数**不是每株的完成度：柳条数量一度也跟着减，结果枝干露出来，一棵柳看着像挂了几根绿丝的枯树；宁可少种几棵，也不要种一片破的。剔掉的树连碰撞体一起剔，不会撞到看不见的树；广场那棵老樟树在手机端也保留，它是广场的构图中心。

## 原有的三片连续区域

三片区域，一个连续的 3D 世界：静屿有海浪、灯塔、营地和岛民；星辉游乐岛有摩天轮、过山车、游客和舞台；旧维多利亚港有密集街区、石砌拱廊、钟楼、轮船和可进入参观的大建筑。跨海栈桥连接两岛，港区可以直接抵达，也可以驾船前往；帆船开到哪里就停在哪里，下船后走回船边再上船。海面不是墙：可以走进海里游泳，从栈桥和岸沿跳水。

陆上采用**第三人称**操控：镜头挂在角色身后，人物朝着实际移动方向转身，走跑动作随速度变化，按 **V** 可以切回第一人称。海滨大道上停着一辆**可以开的老爷车**，走到车边按 **F** 上车。五座大建筑**直接走进去**，室内外是同一套连续碰撞。

## 表面与光

原来的世界是几千个纯色盒子：石板路、灰泥墙、瓦顶、木甲板都是同一种没有质地的平面色，凑近了看不出材料。现在每种表面都挂上一张程序生成的灰度细节图，按**世界坐标**取样——盒子都是轴对齐的，取主轴那一面就够了，不用展 UV，也不会有接缝。贴图只出明暗和起伏，颜色仍旧由原来的调色板决定，所以石板路有了勾缝和每块石头的深浅、墙面有斑驳和墙脚的积垢、瓦顶有一垄一垄的起伏、木料有顺纹和板缝、沙滩有颗粒和浪痕、草坡有一丛一丛的草。起伏用相邻取样求导数，不需要切线数据，平光下的平面也就有了凹凸。地形一张材质从海边的沙一路过渡到山上的草。

光也重新配过。原先三盏灯加起来超过 1，只要颜色稍亮的面就顶到纯白——沙滩是一片白糊，山坡的草也是灰白的，加多少细节都看不见。现在把光压回合理范围，色调映射改成自定义曲线：整套调色板是按 sRGB 挑的十六进制却被当成线性值送进光照，映射前先还原回去，颜色的浓度和明暗层次就回来了。屋檐下和市场里没有弹射光会掉成黑洞，补一盏很弱的常量环境光当作 GI 的替身。天光、地面反光和这盏补光都跟着时段走，所以晨光是暖的、日落是金的、星夜是冷蓝的，夜里的石头不再是白天的颜色。

## 参观维多利亚港

打开后直接站在酒店前的海滨街道，用 WASD 移动、拖动转镜头。**朝大门走过去就进去了**——门洞是墙上真的缺口，走近门自己开，跨过门槛就在大厅里，没有按键、没有瞬移、没有加载。进屋后右侧楼梯直接走上二楼；走近展牌按 E 阅读；原路走出门就回到街上。点击左上角「维多利亚港」可打开建筑导览，选择其他建筑并点击「前往大门」把镜头带到门前。手机使用摇杆和屏幕按钮。

| 可进入建筑 | 室内内容 |
| --- | --- |
| 海关大楼 | 报关大厅、等候长椅、二楼海事档案与阅览桌 |
| 海滨大酒店 | 接待柜台、钢琴休息区、三间独立海景客房 |

街区有 **44 栋沿街建筑**，其中新补入的 14 栋骑楼商铺可以从街边直接走进去。酒店后方的有顶街市可以前后穿行，里面有摊贩和货物；沿海滨还有摊档、手推车、货箱、长椅、彩旗，以及在轨道上往返的电车。钟楼和 7 艘随浪摇摆的船只保留。

桌面端有 80 名行人，手机端为 44 名（连同店员摊贩都是 glTF 角色：四套服装发型、各自一张烘好的贴图，一人一次绘制；走和站的动画按实际速度混合，60 米外降频、260 米外不画），分布在海滨、建筑门前和街市等多条路线；店员和摊贩另行布置。五座主要建筑各开放两层，室内按用途补入休息桌椅、书信工作桌、航海陈列、地毯及墙裙。原有的 30 栋商号与钟楼仍供外观游览。建筑规模、街道布局及室内均为游戏设计，并非史实模型。

港区行人按短时间步连续移动，具有身体碰撞、前方避障、分侧通行和避让玩家的行为。转身渐变，步行动作随实际位移变化，受阻时停步；店员初始位置也会检查家具碰撞。

## 游泳、跳水与下船

海面不再是一堵看不见的墙。从沙滩直接走进海里，水深到齐胸就自动开始游泳：**W / S** 划水、**Shift** 加速，人趴在水面上，镜头贴着浪面跟随。游回浅滩会自己站起来，踩着沙子走上岸。

**空格**跳跃。站在栈桥、石砌岸沿或船上跳下去，落水会溅起一圈水花和几点水珠，落差大时是跳水的姿势。栈桥和港区岸沿站着走不出去，跳起来就能越过——想下水得自己纵身一跃，不会失足掉下去。

爬回岸上：游到码头、栈桥或岸沿旁边按**空格**（手机点右下角「上岸」），角色会翻身上去。够得着的高度约 5.6 米，港区的石砌岸壁、乐园栈桥和跨海栈桥都在范围内，所以不会被困在水里。

## 驾船与下船

帆船是一艘停在世界里的船。开场它系在静屿码头旁；底栏「扬帆出海」或数字键 **3** 把你带回船停着的地方出发，走到船身旁按 **F** 也能直接上船，游泳时贴着船身同样可以。海上按 **W / S** 前进后退、**A / D** 转舵。

按 **F** 或点「下船」就地下船，不再瞬移去找岸：船舷外是沙滩或矮码头就一步跨上去，是高出船舷的石砌码头就翻上去（岸沿那圈拦人的护栏不拦下船的人），是水就跳下去游——**船停在哪，人就从哪下**。船留在原地不动，地图上会画出它的位置，你可以上岸去逛，回来再上船。

港区四周是垂直的石砌岸壁，船能直接靠到墙边，人跳下水后沿墙翻上码头。乐园与港区面板上的「码头出海」「港口出海」是把船叫到该码头来的快捷方式。

停着的船会挡人，走近时绕船身走。

## 驾机翱翔

维多利亚港的木栈桥外侧泊着一架 **1920 年代的双翼水上飞机**。走到栈桥尽头按 **F** 上机，或点底栏「驾机翱翔」（数字键 **6**）回到它停着的地方。

起飞：按住 **Shift** 加油门（手机按住右下角「油门」），浮筒在水面上跑五十来米、速度过 110 km/h 之后拉 **W**（手机把摇杆往回拉），机头一抬就离水，浮筒会溅起一道水花。空中 **W / S** 拉起俯冲、**A / D** 压坡度转弯——飞机是靠坡度转的，压满一圈半径约一百米，正好绕静屿一周。松开油门会自动回到巡航速度（约 150 km/h），不用一直按着。左下角显示高度和速度。

降落：**空格**收油门（手机点「收油门」），压低机头贴着海面落下来，落水会溅起水花；落得太重会提示你下次收油门、压平了再落。停稳之后按 **F** 下机——舷边是码头就翻上去，是水就跳下去游。**飞机停在哪就留在哪**，地图上标着它的位置，你可以飞到静屿或星辉乐园的近海降落，上岸逛完再飞回来。

它是水上飞机，只能落在水面。擦到陆地会被顶起来、掉速度并提示拉起，不会摔机也不会损坏。升限约 340 米，飞出海图范围会被劝返。夜里机腹灯会亮。

从空中能一次看到三片地方：港口的骑楼街市、跨海栈桥、静屿的灯塔和营地、星辉乐园的摩天轮。

## 第三人称与开车

陆上默认第三人称。角色是带骨骼动画的 glTF 模型，待机、走、慢跑、冲刺、游泳按实际状态和速度切换（模型加载不上时退回带肘、膝关节的低多边形人偶，并在画面上提示）；身体朝向跟随位移方向平滑转动，与镜头朝向分离，所以站着转镜头不会带着人转。跟随镜头从肩点向后拉，撞到楼板、墙面或街景会自动收近，进入建筑室内时进一步缩短，滚轮可调距离。按 **V** 在第三人称与第一人称之间切换，第一人称回到原来的视角高度并隐藏人偶。

海滨大道旁的车道（约 x=650, z=-148）停着一辆老爷车。走近车身会出现「上车 · F」，按 **F** 或点按钮上车；底栏的「开车兜风」和数字键 **5** 会直接把镜头带到车上。下车会检查车旁空地；空间不足时先挪车。

| 驾驶操作 | 说明 |
| --- | --- |
| W / S | 油门、刹车；停住后继续按 S 倒车 |
| A / D | 转向（自行车模型，车速越高方向角越收紧） |
| 空格 | 手刹 |
| 拖动 / 滚轮 | 临时环视车身、拉远拉近；松手后镜头自动回到车尾 |
| F | 下车，角色从驾驶侧站出来（被挡住会绕车找空位） |

车辆扫掠碰撞覆盖车头、车尾、车轮和转弯过程中的车身范围；撞墙或接近行人时会被挡住并掉速，也限制驶入海面和二楼。行人会主动绕车，星夜时车头灯会亮。当前使用保守的车身包围盒，斜着贴墙时会留出一些余量，尚未加入车损、撞人反应或交通系统。

步行和驾驶的跟随镜头都检查完整后拉路径，贴墙时允许收近到角色旁边，不再用固定最小距离把镜头推入墙内。

玩家角色已换成带骨骼蒙皮动画的模型，路人和场景仍是简化模型：**没有**交通 AI、任务系统、经济系统或多辆可选车辆。

## 连续的室内外

五座大建筑不再是「走到门口按 E 传送进去」。街面和室内现在共用**同一套碰撞世界**：

- 建筑原本在碰撞表里是一整块实心占地，走近时会换成它自己的墙——正面留着 8 米宽的真门洞，背墙、两侧墙、柱子、家具照旧是实心的。所以只有门洞能过，撞哪面墙都还是撞墙。
- 门前那段柱廊挪开了正对门洞的柱子，留出一条干净的通道。
- 脚下高度由**所在位置**决定，不再由「有没有按过 E」决定；楼梯是一段连续的斜面，走上去就到二楼，走下来就回一楼。
- 跨过门槛时自动切换室内界面（房间名、灯光、离开按钮），走出门自动收回。门会在你走近 15 米时自己打开。
- **E 键现在只用来读展牌**，进出门完全不需要按键。面板上的「离开建筑」按钮保留，作为直接回到门前的快捷方式。
- 行人路线原本正好横穿三座建筑的大门口。现在这些路线拆成绕开门洞的两段，行人也会主动离开门前 7 米；门口仍保留人物碰撞，遇到行人需要绕开或等他走过。

## 躲猫猫

在「維多利亞港」面板点「躲猫猫」开始。三名搜查员（手机端两名）背过身数 20 秒，你去躲；躲满 3 分钟算赢，被摸到就输。左侧面板实时显示剩余时间、最近搜查员的距离，以及每个人当前在干什么。

他们不是靠「知道你在哪」找人的：

| 能力 | 怎么做的 |
| --- | --- |
| **看见** | 视野 118°、34 米，并做真实遮挡检测——墙、柱子和大件家具挡视线，椅子长凳不挡。背对着你就看不见；5.5 米内不用正对也能察觉。走路时头会左右扫。 |
| **听见** | 声音穿墙。站着不动没声音，走路 9 米，**跑步 25 米**，开车 26 米起、越快越响。听到的位置带误差，离得越远越不准——他们会去错地方翻。 |
| **记忆** | 追丢之后不会"忘记"，而是奔向你最后出现的位置，在那一带找上十几秒才放弃。 |
| **通报** | 任何一个人看见你，其余人立刻收到警报点并往那边收拢。 |
| **分工** | 没有线索时按 x 坐标把港区分成几片，各搜各的；挑目标时还会避开同伴正在去的地方，不会三个人挤成一团。 |
| **进屋搜** | 走的是和你同一套碰撞和同一批门洞——他们会推门进楼、走楼梯上二楼翻，不是只在街上转。 |

寻路用的是一张按需生成的巡逻图：街面 24 米网格 + 五座建筑每层 7 米网格，边是"能不能直着走过去"（身体半径扫描），门洞和楼梯是仅有的两处跨层连接。生成后只保留和街面连通的部分，所以搜查员永远不会挑一个走不到的目标。图在开场 4 秒后趁空闲预先建好（约 130 毫秒），点开始时是即时的。

搜查员本身每帧约 0.18 毫秒。

## 打开游玩

下载仓库并解压，用支持 WebGL 的现代浏览器打开 [`index.html`](./index.html)。场景、Three.js 和合成声音都包含在 HTML 中，核心玩法可以离线运行，不需要 API 密钥或安装依赖。

**例外：所有的树。** 六个地区的植被现在都是 `assets/trees/` 里的 glTF 模型（见下面的「六地的树」）。浏览器会按跨域规则拦掉 `file://` 发出的模型请求，所以**直接双击 `index.html` 打开，树不会出现**，画面上会给出提示、控制台另有一条 CORS 报错——按规则是响亮报错，不会悄悄退回旧的圆柱棕榈。玩家角色（`assets/player/` 的蒙皮模型和动画）同理：加载不上时画面提示「显示的是旧的简易人偶」，控制台报错。地形、建筑、船、人物、玩法都照常。

要看到树，用下面任一种：

```sh
python START_GAME.py      # 不需要装任何东西
npm run dev               # 需要 Node.js 22+
npm run package:game      # 出 dist 单文件版，双击打开就是完整的六地
```

单文件版把模型和贴图一起 base64 内嵌了，所以它双击打开是完整的，不受这条限制。

也可以在装有 Node.js 22 或更新版本的电脑上运行：

```sh
npm run dev
```

随后打开终端显示的本地地址。

## 实时同游（可选）

点右上角「联机」可填写名字并创建 8 位房间码，把邀请链接发给朋友后即可在同一世界里看到彼此的位置、朝向、移动状态与上下线，并使用房间内的临时文字聊天。联机组件不可用或网络中断时，原有单机玩法仍可正常运行。

位置在游戏更新后定期广播；新玩家直接出现在其当前位置，普通移动平滑显示，跨区域的大距离跳转直接切换。连接中断时显示「重连中」并暂停发送，恢复连接后重新登记在线状态。房间人数变化不会覆盖已经收到的最新位置。

当前联机是轻量的社交同游层：同步角色位置，不同步碰撞判定、车辆归属、钓鱼结果或游乐设施进度；聊天只在当前房间临时广播，不写入数据库。随机房间码不是账号权限，请只把链接发给认识的人。

联机使用 Supabase Realtime 的临时 Presence/Broadcast 频道，不需要创建数据表。部署者若替换 Supabase 项目，需要在 `online.js` 中替换 publishable key，并确保该项目允许公开 Realtime 频道。

通过本地预览运行时，请用房间码让不同设备加入各自打开的游戏网址；本机 `127.0.0.1` 邀请地址不能直接发给远方朋友。公开游玩使用上面的 GitHub Pages 在线地址。自行下载仓库时应保留 `online.js`；联机组件和 Supabase 服务需要网络连接。

## 当前实现

- 单一 Three.js 场景、渲染器和相机，共用海面、昼夜、地图、声音开关和拍照。
- 第三人称角色与跟随镜头：独立人偶骨架、朝向与镜头分离、镜头碰撞收近、第一人称切换。
- 一辆可驾驶的车：自行车转向模型、油门刹车倒车手刹、复用港区扫掠碰撞、自动回正的跟车镜头、上下车流程。
- 室内外单一碰撞世界：建筑实心占地按需换成带门洞的墙体，脚下高度与楼层由位置推导，进出屋无按键无瞬移。
- 9 种游乐设施及舞台，共 10 个乘坐或观演座位视角。
- 港区的建筑有室内墙体与家具碰撞、可步行上下的楼梯、门扇动画和透光海景窗；夜间窗户与室内灯光点亮。
- 港区从实际模型生成墙体、柱子、长椅、灯柱和摊档支架等碰撞范围，检测整段移动并沿障碍滑动。行人与电车也会阻挡玩家；码头边缘和二楼楼梯口设有限制。
- 游客沿路线活动，设施循环运行；尚未实现完整排队上车、经营或多人联机。
- 表面细节：程序生成的灰度贴图按世界坐标主轴三平面取样，明暗、粗糙度与导数凹凸三处注入现成材质的着色器，不改几何、不改调色板；地形按高度在沙与草两层之间过渡。手机降到 128 像素并关闭凹凸。
- 光照与色调映射：自定义曲线在映射前把 sRGB 调色板还原成线性，日／黄昏／夜三套天光、地面反光与补光随时段插值。
- 重复模型使用实例化，静态园区模型按材质合并；手机减少游客与树木数量。
- 港区的静态物件完成实例化后移出重复的场景层级，只更新行人、门扇、船与电车的实例变换。
- 单文件结构方便分发；后续可以按地形、设施、角色、输入等模块拆分。

npm test

检查覆盖两种屏幕尺寸下的场景初始化、岛民寻路、栈桥双向通行、10 个座位视角、退出乘坐、走进海里开始游泳并游回沙滩上岸、跳跃高度与落地、跳过栈桥与港区岸沿的护栏落水后翻上岸、就地下船（水里与码头两种）、船留在原地并可再上船、船身挡人、从栈桥上机、滑跑起飞、爬升到升限、满坡度盘旋半径、海图边界、低空掠过码头被顶起、落水与滑停后下机、飞机留在原地，以及原有钓鱼状态变化。港区检查覆盖五座建筑的进出、楼梯双向通行、展牌互动、墙体与家具碰撞、海景窗开口、切换区域后的室内状态清理，以及海堤阻挡船只。街区增补检查包含开场步行抵达酒店、穿过整座街市、直接走入骑楼店铺，以及行人路线避开建筑和摊档。

检查使用内嵌的真实 Three.js 场景对象和模拟 DOM/渲染器，**不覆盖实际 GPU 着色器、浏览器画面、音频播放或设备帧率**。

烟雨渡的树另有一项：`npm test` 跑在 Node 里，没有 XHR，加载不了 glTF，所以那边**只有那里**会退回旧的球体树（浏览器里加载失败是报错，不是悄悄换回旧树）。检查比对两条路线，确认柳树/杂树的落点数、碰撞体，以及树那一段之后的随机种子完全一致 —— 树少抽几百个随机数，后面的宝塔、远山、菜畦就会整片移位，`skipTo()` 守的就是这件事。树在画面上长什么样只能靠截图看：`node tests/tree-shots.cjs <目录>`。

联机回归检查运行两个独立客户端，覆盖连续位置广播、发送频率、成员变化不回退坐标、断线与重新登记、离开房间后忽略迟到消息，以及异步重连期间离开。游戏场景检查还验证实际帧循环调用联机更新、新玩家出生位置、普通移动插值和跨区跳转。

真实网络检查先运行 `npm ci`，再运行 `npm run test:online-live`。它会在已配置的 Supabase 项目创建一个随机临时测试房间，验证两端多次移动、聊天、真实 WebSocket 断开后的自动恢复和离开房间；结束时断开测试客户端。该检查使用真实网络与 SDK、模拟界面，不要求另开本地服务器或浏览器。浏览器界面测试 `npm run test:online-browser` 另需可用的 Playwright/Chromium，并启动端口 8766 的预览服务。

碰撞回归检查包含：高速斜穿薄墙、连接墙角、重叠障碍恢复、柱子和长椅、海堤边缘、长帧间隔下奔跑、行人阻挡、电车挤压，以及二楼楼梯口防跌落。

室内外连续性检查覆盖：五座建筑各自从街上一路走进去（记录跨过门槛的帧，并确认玩家真的位移过而不是被摆进去）、走上二楼再走下来、原路走出门回到街面高度，以及正面偏移四处、背墙、两侧墙都仍然挡人。

第三人称与驾驶检查覆盖：人偶显示与朝向跟随位移、跟随镜头不穿地面且室内不出墙、视角切换、车位无碰撞、整条海滨大道加速到路速、A/D 转向方向与转向率、撞墙不穿模也不下海、倒车与手刹、下车点落在可站立的路面上，以及上下车提示的出现与消失。

驾驶碰撞回归直接检查真实 Three.js 车身几何的边界，包含保险杠、转向车轮、悬挂倾斜、车尾倒车、斜向撞墙和转弯中途扫到墙的情况；另检查步行与驾驶镜头贴墙收近、车辆与静止/移动行人的间距，以及门洞里的行人仍能阻挡玩家。

人群回归检查连续模拟 90 秒，逐步检查移动是否连续、人物是否进入静态障碍、行人是否互相重叠及是否能持续行走；另模拟 20 秒绕开静止玩家的情况。桌面和手机配置分别运行。

- `index.html`：可离线打开的完整合并版（树需要起本地服务，见上）。
- `tests/smoke.cjs`：核心逻辑检查。
- `online.js`：可选联机客户端。
- `tests/online.cjs`、`tests/online-harness.cjs`：联机状态与双客户端回归检查。
- `tests/online-live.cjs`：真实 Supabase 双客户端移动和断线恢复检查。
- `tests/tree-shots.cjs`：烟雨渡的树，改前改后同机位对比截图。
- `scripts/serve.mjs`：仅绑定本机的静态预览服务。
- `assets/trees/`：烟雨渡的树模型与贴图，来源见 `assets/LICENSES.md`。
- `assets/player/`：玩家角色，`player.glb`（模型）+ `anims.glb`（动画），来源见 `assets/LICENSES.md`。
- `journeys/assets.js`、`journeys/vendor/GLTFLoader.js`：外部 glTF 的加载。
- `journeys/foliage.js`：六地共用的植被装配（实例化、风、alpha 卡片）。
- `scripts/fetch-tree-sources.mjs`、`scripts/prepare-tree-assets.mjs`、`scripts/make-plant-cards.mjs`：树资源的下载、重打包，以及柳条/竹叶/松针卡片的生成。原件放在不入库的 `assets/_src/`。
- `scripts/fetch-player-sources.mjs`、`scripts/prepare-player-assets.mjs`、`blender/tools/compose_player.py`：玩家角色的下载（itch.io 常限流，失败时脚本会给出手动下载步骤）和加工（要 Blender 5.2，路径可用环境变量 `BLENDER` 指定）。验收截图：`node tests/player-shots.cjs`。
